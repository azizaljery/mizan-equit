# API الاختبار التاريخي

`POST /api/backtest`، من أصل الموقع نفسه وبجلسة حساب المالك. لا تضع ترويسة هوية المالك يدوياً؛ بوابة الموقع الموثوقة هي مصدرها.

```js
const response = await fetch('/api/backtest', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ symbol: 'AAPL', mode: 'full', asOf: '2020-06-15' })
});
const output = await response.json();
if (!response.ok) throw new Error(output.error);
console.log(output.text, output.diagnostics);
```

- `symbol`: رمز الشركة؛ يقبل الأحرف الصغيرة ويحوّلها إلى كبيرة.
- `mode`: `technical` افتراضياً أو `full`. هذا تشغيل تجريبي لـ`analyze` بقاعدة `trader < 40`، وليس `finalDecision`. الوضع الفني الحالي يمرر ماليات فارغة إلى المحرك ولا يعزل شروطه المالية؛ التحذير يظهر في النتيجة. نقص الماليات في `full` يحجب النوافذ ولا يحوّل الوضع تلقائياً.
- `asOf`: آخر تاريخ للأسعار، بصيغة يومية صحيحة، وسابق لليوم UTC. الافتراضي أمس UTC. يجلب المصدر نافذة خمس سنوات تقريباً تنتهي عند القطع، ويستخدم المحرك 504 جلسات تهيئة قبل التقييم. ليس هذا تاريخ بداية استثمار.
- `feeBps` و`slippageBps`: بين صفر و1000 نقطة أساس لكل جانب؛ الصفر الافتراضي مذكور في التحذيرات.
- `pricesAreSplitAdjusted`: تأكيد صريح بعد التحقق من المصدر. عند وجود تجزئة دون التأكيد يفشل الاختبار بـ422. لا يفترض المسار صحة التعديل تلقائياً.
- `benchmarkSymbol`: اختياري، مع `benchmarkComparableBasisConfirmed: true` بعد التحقق من تطابق أساس التعديل. يُجلب المؤشر بتاريخ القطع نفسه، وتُحجب المقارنة إذا اختلفت العملات أو غابت أسعار التاريخين المطابقين. المقارنة لكل أفق مستقلاً.

الاستجابة تحتوي `result` و`text` و`diagnostics` (أعداد BUY/WAIT/BLOCKED وأسباب الحجب وعدد الحقائق المستلمة)، و`sources` (مصدر الأسعار ووقت الجلب وفحوص المصادر). عدد الأسباب قد يتجاوز عدد النوافذ لأن للنافذة أكثر من سبب. نتيجة بلا نوافذ تحمل تحذيرات نقص التاريخ، ولا تدّعي دقة.

يستخدم المسار `fetchCompany` مع `configuredReader` وإعدادات الأسواق والمصادر. لا يستدعي `analyzedCompany` أو `recordAnalysis` أو `resolveForecasts` أو البحث المساعد. لا يحفظ نتيجة الاختبار الجديد أو يعدّل جداول التوقعات؛ سجلات حالة المصادر وحجز طلبات SEC تبقى فعّالة. مسار الاختبار القديم وأرشيفه مستقلان.

الحد الأقصى للجسم 2048 بايت، والتواريخ الحالية/المستقبلية والحقول المجهولة مرفوضة. `400` لمدخلات غير صالحة، `403` للحماية أو السوق المعطل، `413` للحجم، `415` لنوع المحتوى، `422` لبيانات الاختبار غير الصالحة، و`503` لغياب قاعدة الإعدادات. فتح الرابط بـGET يعيد `405`.

الكاش مؤقت وليس أرشيف مدخلات ثابتاً. الأسهم المشطوبة والقطاع التاريخي ونسخ الحقائق المعاد إصدارها وأسعار المزود المعدلة تبقى حدوداً للاختبار. هذه النتائج ليست قياساً لدقة التوصية الحية.

## التحقق عند الإضافة

- نجح بناء الموقع مع تسجيل المسار الجديد.
- 145 اختباراً ناجحاً، وصفر فشل، واختبار قديم واحد متجاوز لأنه يتطلب وحدة المقارنة السابقة خارج المشروع.
- الاختبار التكاملي يستدعي المسار و`fetchCompany` و`configuredReader` والمحرك الحقيقيين، مع استجابات شبكة اصطناعية معلنة وقاعدة SQLite معزولة. يتحقق من القطع للسهم والمؤشر ومن عدم محاولة الوصول لجداول التوقعات، مع استمرار تسجيل حالة المصادر.
- `tsc` يعرض 26 مشكلة لتعريفات Cloudflare غير المتاحة محلياً: 25 سابقة، وظهور المشكلة نفسها لاستيراد `cloudflare:workers` في المسار الجديد. لا أخطاء أخرى في الوحدة أو الربط. نجاح البناء ليس ادعاءً بأن فحص TypeScript العام أصبح نظيفاً.
- لم يُنفّذ اختبار طلب مالك مصادق عليه إلى المسار المنشور بمصادر شبكة حقيقية ضمن هذه الإضافة.
