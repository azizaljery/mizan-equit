# فحوص ميزان — إضافات إلى النظام القائم

الفحص الافتراضي **للقراءة فقط**. لا تعد استجابة HTTP 200، وجود مفتاح Cron، أو عدد التقييمات شهادة جاهزية أو دقة توصية. لا يوجد محرك Backtest أو نظام مصادر جديد، ولا migration جديدة.

## الدخول الآمن

- `MIZAN_HOST`: أصل موقع ميزان فقط، دون مسار.
- `MIZAN_COOKIE`: جلسة الاستضافة الفعلية للمالك مع جلسة إدارة ميزان. كوكي الإدارة وحدها لا تعوض هوية الاستضافة. لا نزوّر ترويسة هوية المالك.
- اضبط الأسرار محليًا؛ لا ترسل الكوكي أو الرمز السري إلى المحادثة أو مستودع المصدر.
- الرد 401/403 يستدعي تسجيل الدخول بالصلاحيات الصحيحة، لا إضعاف الحماية. GET يدعم التصفح المباشر دون Origin، ويرفض أصلًا مخالفًا أو طلبًا cross-site.

## القراءة والتقارير

```sh
npm run verify:full
npm run verify:cron
npm run verify:readiness
```

`verify:full` يشغّل كل جزء مرة واحدة، وينشئ JSON وHTML وMarkdown حتى عند تعثر فحص. يطبع مجلدًا جديدًا داخل `verify-out/run-*` في كل مرة، ولا يكتب فوق دليل سابق. الملفات محلية وليست أصولًا عامة للموقع، ووضع الملفات 0600. إذا اخترت مجلدًا آخر عبر `MIZAN_OUT_DIR` فأبقِه خارج public/ وdist/ ولا ترفعه للمصدر.

رموز الخروج للفحص الموحّد: 3 = تحقق جزئي أو فحوص تحتاج مراجعة؛ 2 = خطأ إعداد/تشغيل. لا يعيد 0 بوصفه إثبات جاهزية كاملة؛ اختبار المتصفح والتكرار الإنتاجي المضبوط غير منفذين فيه. `verify:cron` يعيد 0 فقط إذا اجتاز سجل الدورة شروطه، لا إذا ثبت تسجيل Trigger لدى الاستضافة.

لتحويل تقرير موجود، عيّن `MIZAN_REPORT_PATH` إلى مسار JSON المحدد، ثم `npm run verify:report`. المخرجات بجوار المدخل أو في `MIZAN_HTML_PATH` و`MIZAN_MD_PATH`. التحويل يرفض الكتابة فوق ملف قائم؛ اختر اسمًا جديدًا عند الحاجة.

## اختبارات قد تحفظ بيانات — اختياري وصريح

لا تشغّلها لتجربة الدخول. فتح التوصية قد يحفظ توقعًا عبر المسار القائم؛ التقييم اليدوي يحفظ النتائج؛ Backtest يحفظ تشغيله في الجدول القائم.

```sh
npm run verify:reconcile -- --run 5
npm run verify:private -- --run
npm run verify:backtest -- YYYY-MM-DD YYYY-MM-DD AAPL MSFT 2222.SR
npm run verify:full -- --run
```

- للخاص المنفرد: `MIZAN_SYMBOL` و`MIZAN_RECOMMENDATION_PIN` محليًا. لا تمرر PIN في سطر الأوامر.
- للفحص الموحّد الاختياري: `MIZAN_SYMBOLS` حتى 3 رموز مفصولة بفاصلة بما يطابق حد المحرك الحالي، و`MIZAN_BT_START` و`MIZAN_BT_END` لفترة تحتوي توقعات أصلية صادرة بالفعل. لا نفترض سنة 2024. يتطلب فحص الخاص PIN أيضًا. ما لم تُحدد هذه المدخلات يظهر **لم يُنفذ**.
- `--run` يشغّل المهمة اليدوية مرة واحدة بحد 5، لا مرتين. لا توجد إعادة تلقائية للطلبات التي تكتب. يتوقف تسلسل الخاص عند أول إخفاق لحماية محاولات الرمز السري.
- `MIZAN_RUN_ID` اختياري لإعادة قراءة تشغيل Backtest بنفس إعداداته؛ تغيير إعداداته مع نفس المعرف يرفضه المحرك الحالي. خطة التشغيل تحفظ قبل الطلبات دون أسرار.
- لا يُعتبر تشغيل مكتمل بلا ملاحظات تاريخية قابلة للقياس اختبارًا ناجحًا. التقرير يميز المعلّق والمستبعد والمكتمل.

## مسارات النظام المستخدمة

| الغرض | المسار الحقيقي | الحدود |
|---|---|---|
| الحالة المقسمة | GET /api/admin/state | قائمة ومفاتيح محدودة، حقول صغيرة، لا JSON كامل |
| التحقق الموحد | GET /api/admin/verify | المالك + جلسة الإدارة؛ قراءة فقط |
| الملخص | GET /api/admin/dashboard | نفس التحقق؛ آخر 5 اختبارات و10 نتائج؛ لا جدول جديد |
| تقييم المستحق | POST /api/admin/run-background | المسار الموجود؛ ليس /api/admin/jobs/evaluate-due |
| التوصية | POST /api/private-recommendation | هوية المالك + PIN، لا GET بديل عام |
| Backtest | POST /api/admin/backtest | المحرك الحالي مع التوقعات الأصلية، لا استبدال |

ملخص التوقعات يقرأ forecast_records ويربط forecast_outcomes عبر id؛ حالة النتيجة داخل JSON. صفوف research_state ليست عدد التوقعات. الحالات حصرية: مكتمل، معلّق، غير متاح، مستبعد، أو غير صالح.

آخر تشغيل ليس بالضرورة يدويًا: Cron يكتب أيضًا المفتاح العام. يفحص التحقق triggeredBy، المواعيد، الجدولة، القفل، نجاح الحفظ والعدادات. عدادات ناقصة، JSON تالف، وقت مستقبلي أو دورة جزئية لا تصبح نجاحًا.

قراءة عدم التكرار تعيد الفحص الموجود للاتساق، وتعلن أن الإثبات الديناميكي غير منفذ. لا تُحذف الإصدارات الصحيحة من نوع A→B→A ولا تُخلط مع تكرار متتالٍ.

## ميزان الخاص

بعد فتحه بالطريقة المعتادة يعرض شروط القرار الحالية وأدلتها، والتوقعات الست المحفوظة من نفس التحليل باستخدام مكوّن Forecasts القائم، ثم المحاور والماليات ومصادرها والنواقص. يظل القفل عند إخفاء الصفحة وبعد دقيقتين، ولا تتغير أوزان الشراء أو مصادر الحساب أو إعدادات إظهار التوقعات العامة. بيانات ناقصة تعني حدودًا واضحة، لا أرقامًا أو نسب نجاح مختلقة.

هذه الإضافة لا تثبت سبب اختفاء قسم التوقعات العامة لدى مستخدم بعينه؛ إعدادات الأقسام لم تُصفّر. ولا يثبت نجاح اختبارات البرمجة ربحية التوصية. الذهب والمحفظة وحماية المالك محفوظة دون تعديلات.
