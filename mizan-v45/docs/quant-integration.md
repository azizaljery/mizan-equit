# دمج الوحدات الكمية

أضيف quant-core وregime-engine من الأكواد المسلمة مع تصحيح العقود والأخطاء.

- تقسيم زمني حسب التوقيت الفريد مع فهارس المدخل الأصلي، تطهير الآفاق، استبعاد جلسات الحظر من التدريب اللاحق، وحد أدنى بعد الاستبعاد. يتطلب المستدعي توحيد توقيت الجلسة. الحظر هنا فجوة ثابتة في عينة مجمدة وليست ضمان استقلال.
- المقاييس تستقبل عوائد محفظة دورية غير متداخلة بعد التكاليف، مع تكرار سنوي صريح. لا تستقبل صفقات متداخلة على أنها أيام. حدود 1.2 و12% و2 و0.18 من المقترح وليست حدودًا مثبتة خارج العينة.
- DSR غير محسوب ويعود null؛ القبول يبقى false لغياب توزيع شارب للتجارب ومجموعة تحقق مستقلة. لم يُعتمد التقريب المرسل كاحتمال تفوق صحيح.
- التفاضل الكسري وحدة قابلة للاستدعاء مع إظهار فترة الإحماء والقيم المفقودة. لم يدخل أوزان التوقع الحالي.
- محرك الحالات قواعد ثابتة وليس HMM؛ حقل probabilities للتوافق يمثل أوزانًا غير معايرة مع calibrated=false. المدخلات الناقصة أو غير الصالحة لا تنتج حالة افتراضية. الحالة العرضية تشمل حالات هبوط لم يميزها النموذج المقترح.
- tradeScenario يستخدم المحرك المشترك، ينتظر عند الصدمة أو غياب التصنيف الصاعد، ويحدد الهدف الأول عند 1.8 ضعف الخطر. المستويات تبقى رقمية لتوافق القرار النهائي والمحفظة. أسباب الانتظار منفصلة عن شروط الخطة.
- غرفة القرار تحتفظ بتحليل الماليات المحقق والتقييم متعدد الطرق والسجل. أضيفت حالة السوق دون افتراض P/E=15 أو نقد ودين صفريين أو قيمة عادلة من السعر الحالي. لا إعادة حساب للتوقع من رقم سعر بدلاً من LiveQuote.
- واجهة التوقعات بطاقات، مع الاحتفاظ بالست مدد وروابط الاختبار والتوقع المسجل والمصادر والإبطال. تعرض الحقول الفعلية؛ لا ادعاء GJR-GARCH أو Conformal أو Q10/Q50/Q90 لم ينتجها المحرك.

اختبارات محلية منفصلة عن الاتصال الحي وعن اختبار Walk-Forward كامل: npm run test:quant وnpm test وnpx tsc --noEmit. لم يتم تدريب نموذج أو إجراء مقارنة أداء خارج العينة. quant-core جاهز للاستدعاء، ولم يستبدل runner التاريخي الحالي تلقائيًا.
